# AGENTS.md

Guidance for coding agents (and people) changing this repository. Read this before editing.

## What this repository is

A catalogue of agent architecture patterns with tested reference implementations and reproducible comparisons. Its value is that every claim is either cited or measured, and every number on a page is regenerated from code. Protect that property above all else.

## Commands

| Task | Command |
|---|---|
| Install | `pip install -e ".[dev]"` |
| Run all tests | `pytest` |
| Run one test file | `pytest tests/test_loops.py` |
| Run one example | `python examples/01_react_loop.py` |
| Quick experiment run (prints, writes nothing) | `python -m experiments.run_all --n 40` |
| Regenerate published results | `python -m experiments.run_all --perf` |
| Regenerate docs and explorer data | `python scripts/build_catalog.py` |
| Check nothing generated is stale | `python scripts/build_catalog.py --check` |
| Re-verify citations (needs network) | `python scripts/verify_sources.py` |
| Explorer type-check and build | `cd explorer && npm run build` |
| Explorer browser smoke test | `cd explorer && npm run smoke` |
| Build the MCP server for interop tests | `cd integrations/mcp-tool-server && npm install && npm run build` |

## Rules that are enforced by tests

1. **Determinism.** No wall-clock time, `random`, `hash()`, UUIDs, threads or network in `src/agentlab` (outside `integrations/`), `experiments/` or `tests/`. Use `core.util.u01(*key)` for randomness and `SimClock` for time. `tests/test_experiments.py` runs every experiment twice and compares digests.
2. **Published results match the code.** If you change anything that alters a result, run `python -m experiments.run_all --perf` then `python scripts/build_catalog.py` and commit the outputs. `tests/test_experiments.py` and `tests/test_catalog.py` fail otherwise.
3. **Generated files are never edited by hand.** These carry a "Generated by" comment: `patterns/*/README.md`, `patterns/README.md`, `docs/decision-guide.md`, `research/SOURCES.md`, `experiments/RESULTS.md`, everything under `explorer/public/data/`. Edit the source (`pattern.toml`, `guide.toml`, `sources.toml`, experiment modules) and rebuild.
4. **Numbers in prose are bound to results.** In `pattern.toml` and `guide.toml` write the five fields `experiment|scenario|arch|key|fmt` between double curly braces. In hand-written Markdown wrap the number in an HTML comment pair carrying the same five fields, for example `<!--n:loops|clean|react|model_calls_mean|0-->16<!--/n-->`; the build refreshes the value between the comments. `fmt` is `%`, `k` (thousands), `s` (ms to seconds) or a digit count. Never type a measured number without a binding.
5. **Citations resolve.** `[label][key]` must use a key from `research/sources.toml`. The build appends link definitions and fails on unknown keys. Only write a claim about an external system if you fetched the source and read it; record how in `verified` and `note`.
6. **Every implemented solution has an implementation, a runnable example and tests**, all named in its `pattern.toml` entry. The build fails otherwise.
7. **Examples run standalone** with exit code 0 (`tests/test_examples.py`).

## Architecture invariants

- Loops and orchestrators depend only on `core.types.Model` and `core.types.ToolExecutor`, and call them only through `core.runtime.Runtime`. Do not call a model or tool directly from an architecture: metering, tracing, journaling and replay all depend on that single path.
- Policies (retry, breaker, idempotency, permissions, journal, crash injection, registries) are `ToolExecutor` or `Model` wrappers. Add behaviour by wrapping, not by adding parameters to loops.
- The simulated model (`sim/model.py`) is stateless: its answer is a pure function of (seed, profile, request). It knows the task's solution structure but only the values visible in its messages. Do not give it hidden memory; several experiments are meaningless if it has any.
- Noise is paired: a slip is drawn from `u01(seed, task, step, attempt, ...)`. Keep new error sources keyed the same way so architectures face identical faults.
- Message `meta` is the structured channel the simulator reads; `content` is what is tokenised. Build messages with `core/messages.py`.
- `SimulatedCrash` derives from `BaseException` on purpose. Never catch `BaseException` in library code.
- Task success is judged on the final world state by `sim.tasks.evaluate`, never on the agent's own report.
- The explorer contains no agent logic and imports nothing from Python. It reads `explorer/public/data/*.json`.

## Adding to the catalogue

Follow [`docs/extending.md`](docs/extending.md). In short: implement against the protocols, add an example and tests, add or extend an experiment, describe the solution in `pattern.toml`, rebuild, and make sure `pytest` and `build_catalog.py --check` pass.

## Style

- Python: standard library only in `src/agentlab` (optional extras live in `integrations/`). Type hints everywhere. Small modules; docstrings explain why, not what. Line length up to about 200 is accepted in data-heavy lines.
- TypeScript: `strict` and `noUncheckedIndexedAccess`. No `any`.
- Explorer UI: dark mode only, tokens in `explorer/src/index.css`. One measure and one axis per chart; status is icon plus words.
- Documentation: separate what was **measured** from what is **recommended**, and state the limitations of a measurement next to it.
- Do not put model identifiers of the tool that wrote a change into commits, code comments or documents.

## What not to do

- Do not add a dependency on an agent framework to `src/agentlab`. Framework equivalents are described in `research/frameworks.md` and the `frameworks` field of each solution.
- Do not report a test, benchmark or publication step as done unless you ran it and it passed. If something could not be run (for example the live-API adapter), say so in `docs/limitations.md`.
- Do not weaken a test to make a change pass. If a measured result legitimately changes, regenerate results and update any claims bound to them.
